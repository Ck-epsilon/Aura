# 新读写工具的自我审计

对 `read-core.mjs` / `locator-api.mjs` / `anchor-core.mjs` / `aura-edit/index.js` / `aura-read/index.js`
的通查。判定标准与之前一致：**凡是"用一个机制盖住另一个机制的问题"就是补丁；
凡是"同一个缺陷修两遍"就是重复实现留下的漏改。**

共找出 **9 处**，全部已修。按危害排序。

---

## 1. 输出 schema 漏声明 `text` —— 每一条成功路径都失败（最严重）

`aura_read` 的渲染器返回 `text`，而 `output.schema` 里**没声明它**，且
`additionalProperties: false`。框架直接拒绝：

```
tool "aura_read" returned invalid output: "value.text" is not a declared property
```

**我的 load-test 当时 29/29 全绿**，因为它从不校验输出是否合工具自己声明的 schema。

这是本项目里第二次栽在同一个模式上：**mock 比框架宽松，就等于没测**。
（第一次是 Cordis 的 `inject` guard——mock 允许未声明的 `ctx.tools` 访问，真机直接抛错。）

修法缺一不可：补上声明；**给 load-test 加输出校验**，并验证那道校验真的能抓到该 bug
（临时移除声明 → 报出与框架一致的错误）。

## 2. 恢复提示用的是声明顺序 —— 我修了地图，漏了它

`directoryHint` 给失败回执提供"这文件里有哪些符号，改用名字再试"。它写的是
`listSymbols().slice(0, 24)`，即**声明顺序**。

而我刚在地图里修掉同一缺陷：按声明顺序取前 24 个，**49% 是函数内局部量**。
于是 `aura_edit` 的恢复提示给模型的，恰恰是最没用的那些名字。

**根因是重复实现**：地图与恢复提示做的是同一个决策，却各写了一份。抽出 `rankSymbols` 共用。

## 3. 循环依赖

`rankSymbols` 放进 `read-core` 后，`locator-api` import 它形成
`read-core ← locator-api → read-core`。ES module 的求值顺序让它**侥幸工作**，但那是脆的。

修法不是调整 import 顺序（那是补丁），而是放到依赖图的正确位置：`struct-core` 零依赖，
只依赖符号表的 `rankSymbols` 归它。

```
struct-core  → (无)          anchor-core  → (无)
read-core    → struct-core   locator-api  → struct-core, anchor-core
```

## 4. `auto` 的目标函数漏了一项：只看"省多少"，没看"是否回答了问题"

**真实模型用出来的。** 它在一个 14 行文件上拿到地图后的反馈：

> 这对大文件是正确的经济选择，在这里是错的：模式选择在全文就是整个答案的文件上优化了字节数。

它说对了。**地图的价值随文件增大而上升**：小文件上全文完备，地图只给名字、反而不完备。
于是 `auto` 补上内容门槛——全文装得下就直接给全文。

这条也说明：**"最小"只是代理指标，不是目标**。目标里还有一项"这选择回答得了问题吗"，
而那一项无法从体量算出来，只能从一次真实使用里学来。

## 5. `ENVELOPE_RESERVE = 1100` 是一个拍的魔数

内容预算 = `PRUNE_BUDGET - 信封预留`，而预留是我随手写的。两个毛病：没有依据；
一旦实际信封超过它，内容预算就偏大，整个结果可能越过剪枝阈值被砍——正是这套设计存在的理由。

改成**算出来**：先按保守预算渲染，量真实体量，超了就收窄，迭代几轮。

第一次改还错了：我用**字符数**估开销，而预算是按 **JSON 序列化**算的——`text` 里的换行
在 JSON 里是 `\n`（两个字符）、引号要转义，字符数系统性低估。实测 49 个组合里 4 个因此超预算。

## 6. 单行 160 字符上限：两级截断，正是我批评过的形状

它**与字符预算机制重复**——两个各自合理的机制叠在一起，产出既不完整、也不说明的输出。
这正是我审计旧 `read` 时指出的毛病。

现在只有一个机制：按预算收行。单行本身超过预算就整行收下并说明它吃掉了整个预算。

## 7. `fitWithin` 的返回值语义不唯一（只撒谎，不报错）

超预算分支返回"实际收下的行数"（含表头），不超预算分支返回传入的 `totalRows`（不含表头）。
同一字段两种含义，调用方按一种解释就差了 1——**明明全渲染了，却报"丢了一个"**。

## 8. 输出里引用了我刚废弃的接口

地图改成按预算填之后，`next` 提示还在写 `mode=map limit=55`——而 `limit` 已不再是参数。
**把过时的接口写进给模型的指令，比不写更坏。**

## 9. 缺失文件不记录观测 —— 看起来无关的报错

`aura_read` 遇到不存在的文件直接抛错，**没有发出 `{kind:'absent'}` 的观测**。
DSH 的契约要求记录——不记录的话，后续 `write` 无法走"带防护的创建"，
会在写入侧失败，**且失败原因看起来与读取毫无关系**。

---

## 判定为设计、不是补丁的两处

`symbolHint` 在结构索引失败时返回 `''`；`directoryHint` 在无符号时返回 `null`。
理由：这两处都是**给失败回执追加恢复建议**，建议生成失败绝不能掩盖原始错误。
注释写明了这一点。保留，但记录在案：它们的沉默是刻意的。

## 命名

工具与包按 `aura` 前缀命名，与内置工具平行便于区分：

| | 工具名 | 包名 | 目录 |
|---|---|---|---|
| 读取 | `aura_read` | `dsh-tool-aura-read` | `aura-read/` |
| 编辑 | `aura_edit` | `dsh-tool-aura-edit` | `aura-edit/` |

引擎层（框架无关）留在 `locator-lab/`，不带前缀——它不是工具，是被适配的对象。

## 审计方法（供下次复用）

1. **校验输出形状**。mock 不校验 schema，就等于没测。这一条本轮又抓到一次。
2. **两列分开量**。一个数同时被两个机制解释时，它证明不了任何事。
3. **搜重复实现**。同一个决策出现在两个文件里，就一定会有一处漏改。
4. **搜裸数字**。每个魔数问一句：它是约束，还是我拍的？
5. **搜语义不唯一的返回字段**。同一字段两种含义，是"只撒谎不报错"类 bug 的主要产地。
6. **搜输出里引用的接口是否还存在**。过时的指令比没有指令更坏。
7. **拿真实模型用一次**。本轮最严重的一处设计缺陷（auto 漏项）与一处实现缺陷
   （schema 漏声明）都是真机用出来的，测试全绿也没发现。
   **mock 与自测能证明"没坏"，证明不了"有用"。**

# 第二轮补丁审计

审计范围：`struct-core.mjs`、`anchor-core.mjs`、`read-core.mjs`、`locator-api.mjs`、
`aura-read/index.js`、`aura-edit/index.js`（约 3450 行）。
方法沿用上一节那七条，另加一条独立复核（子代理只读不写，避免作者偏见）。

## 10. 双义字段复活：用 `imp === 3` 反推"是否导出"（两处）

`rankSymbols` 里**已经算出** `isExported`，却在返回值里把它丢掉、只留一个分数 `imp`。
于是两个消费方各自反推：

- `read-core.mjs:505` 用 `imp === 3 ? '★' : ' '` 决定地图上的星标
- `locator-api.mjs:192` 用 `exported: imp === 3` 填恢复提示里的字段

一个数字同时承担"重要性排序"与"是否导出"两种含义。**一旦重要性分级扩容
（比如再加一级 4 = 导出的类型），"导出"会静默变成别的东西而没人发现**——
而且两处都要改，正是第 3 条审计方法针对的形状。

修法不是在这两处各加一句注释，而是让 `rankSymbols` 把已算出的布尔值带出来：
`return { s, imp, exported: isExported }`，两个消费方改为直接读 `exported`。

## 11. `dropped` 里的硬编码 `- 5`：同一个事实写两遍

`renderDigest` 先手工拼出五行表头，再用
`dropped = signatures.length - Math.max(0, kept.kept - 5)` 反推丢了几条签名。
那个 `5` 是"表头恰好五行"这个事实的手工副本：头少一行就少报一条，多一行就多报一条，
**而且不报错，只是安静地把"还剩几条"说错**。

这和第 7 条（`fitWithin` 的 `kept` 语义不唯一）是同一类病：同一个事实存在两处。

改成从表头定义派生：`heading` 数组先建好，`parts = [...heading, ...signatures]`，
`dropped` 用 `heading.length`。实测 400 个函数的文件仍报 166 条丢弃，与逐行数一致。

## 12. 超过预算的单行会让**整个文件读不出一个字**

最严重的一处。`windowEnvelope` 里预算判断排在前面，于是只要某一行自己就超过
`contentBudget`，循环立刻 `break`、`rows` 为空：

| 单行长度 | `lines [1,1]` | `full` | `around` | `auto` |
|---|---|---|---|---|
| 3000 | 正常 | 正常 | 正常 | 正常 |
| 8000 | **text=0** | **text=0** | **text=0** | **text=0** |
| 20000 | **text=0** | **text=0** | **text=0** | **text=0** |

唯一例外是 `search`（它给匹配处的字符窗口）。更坏的是 `next` 还在建议
`mode=lines lines=[1,1]`——**让模型重试刚刚返回空内容的同一个调用**，是个死循环。
压缩 JS、单行数据、单行配置都会触发。

有意思的是原注释写着"整行收下（信息完整）"：那段意图在
`if (rendered.length > base.contentBudget)` 分支里，但那个分支**永远不可达**——
预算判断先命中并 `break` 了。**注释描述的是意图，不是行为。**

> **对本文第 6 条的更正。** 第 6 条写"单行本身超过预算就整行收下并说明它吃掉了整个预算"，
> 那句话从来没有成立过。改成整行收下也不对——整行收下会让信封越过剪枝阈值，
> 把两级截断的问题重新引入。现在的做法是**行内截断并显式标注**：
> 给前面一段、标 `[truncated]`、并在 `truncated` 字段里给出机器可读的
> `{line, shown, omittedChars}`。担心"切掉行尾会让模型以为这行就到那里"是对的，
> 所以标注必须显眼；但"什么都不给"并不能保护模型，只是把不可读换成了另一种不可读。
> `next` 也相应改指向 `mode=search`——单行内部再切只有它做得到。

## 13. `budgetWarning` 是死分支，且一旦触发会让整条调用失败

收敛循环末尾有个自检：

```js
if (serializedSize(result) > PRUNE_BUDGET) {
  return { ...result, budgetWarning: `serialized size … exceeds …` }
}
```

两个问题：

1. **`budgetWarning` 不在 `output.schema` 里**，而 schema 是 `additionalProperties: false`
   → 这个分支一旦触发，框架会以"未声明字段"拒绝**整条输出**。自检非但没报告问题，
   反而把"输出偏大"升级成"工具报错"。
2. **它触发不了。** 让循环退出而不 break，需要连续 4 轮每轮收窄都小于超出量，
   即 `size - PRUNE_BUDGET < 64`；而每轮收窄后 `size ≈ budget + 信封开销`，
   信封开销远大于 64。实测连 400000 字符的单行都没触发——因为超过预算的行
   现在会被截断（第 12 条），`size` 反而降到 233，单调性成立。

按第 5 条审计方法，**死代码必须删掉或让它真的可见**，不能留一段"注释说它在自检、
实际永远不会响起"的代码。这是本轮唯一未修的一处，因为它需要一个观察面：
正确做法是把这条事实放进 `omitted`（已声明、模型一定看得到），而不是新增字段。
留待下次连同"信封开销上限"一起处理——现在改只是把一个不可达分支换成另一个不可达分支。

## 本轮判定为**设计、不是补丁**的三处

- `PASSTHROUGH_FIELDS` 从集合派生（见下条），不是"再补一行"。
- `symbolHint` / `directoryHint` 在失败时返回空值：第 98 行已记录，仍然成立。
- `HINT_LIMIT = 24`：注释说它是"能放下的 24 个"而非"最有用的 24 个"。
  实测它确实不受预算约束保护（工具层会剪枝），但**剪枝是有标记的**，
  所以这里退化的是紧凑度、不是正确性。判定为可接受，但注释应改说"约"。

## 14. 手写透传清单：四次事故的同一个成因

`aura-read/index.js` 的 `execute` 原本逐个展开要返回的字段：

```js
...(env.omitted === undefined ? {} : { omitted: env.omitted }),
...(env.next === undefined ? {} : { next: env.next }),
…
```

而"引擎给了、schema 认了、中间的透传忘了"已经造成四次事故：
漏 `text` 声明、`version` 在部分模式 undefined、`version` 为 null、`truncated` 漏传。
**前三次的修法都是往这份清单里再加一行——那是补丁的补丁：治的是症状，
而"手写清单会漏"这个成因一直在。**

现在清单从 `PASSTHROUGH_FIELDS` 派生，并加了一条契约断言：
schema 声明的可选字段集合 **必须等于** 透传集合。于是漏一个字段会让测试变红，
而不是等到真实会话里整条调用被框架拒绝。

## 本轮结论

- 架构分层**成立**：四个引擎文件里没有任何框架概念进入代码（命中的全是注释）。
  引擎与适配器的边界没有被侵蚀。
- 最严重的问题不在引擎算法，而在**接缝**：引擎 → 工具壳 → 框架 schema 这条链上，
  每一环单独看都对，合起来会静默丢失或直接报错。
- 第 14 条是唯一一处"成因级"修复；其余是具体缺陷。**接缝仍然是本组件最薄的地方。**

## 15. 死导入：`aura-edit` 还留着 `indexStructure` 与 `listSymbols`

两个符号已导入但无任何使用。它们正是第 171 行注释所说"不再自己挑前 24 个符号"那次
改动的残留——**代码改对了，入口没收干净**：`aura-edit` 仍然直接依赖 `struct-core` 的两个内部函数，
而它实际只需要 `langOf`（判语言）与 `directoryHint`（取目录）。
死导入的害处不只是噪声：它让"这个适配器还能自己建索引"看起来是允许的，
下一个人想挑符号时就有一个现成的入口可用——而那正是被删掉的那个错误做法。

删掉后，`aura-edit` 对 `struct-core` 的依赖收窄到 `langOf` 一个符号，
结构决策只剩 `directoryHint` 这一个入口。

## 审计工具本身的一次偏差（值得记）

我给六个文件写了个"未使用导入"检查器，它把 `read-core` 里**真正在用**的
`rankSymbols` 报成未使用。两个错都在检查器：

1. 它按"整行是否以 `*` 或 `//` 开头"判断注释，于是只看得到独占整行的注释；
2. 更隐蔽的是，它用带 `/g` 的正则做 `.test()`——`lastIndex` 会跨行残留，
   于是判定结果取决于上一次调用停在哪。

第 2 条正是 `FINDINGS.md` 里记过的那个形状：**检查器本身有偏，比被测对象出错更隐蔽。**
改成"先剥注释、再取词"后，六个文件全部干净（`rankSymbols` 也是真在用）。
按第 3 条审计方法：**报出来的每一处都要回源码复核一遍再改**，这次就这么挡住了一次误删。

# 第三轮：正则字面量——本文件最贵的缺口（已修）

由一次独立复核（子代理只读审计）发现，我逐条实测确认后修复。

## 16. 配置表缺了"第三种词法类别"，导致索引器连自己的引擎都读不懂

**症状（实测）**：`read-core.mjs` 有 10 个顶层 `function` 声明，索引只认出 **2** 个：

```
真实: renderChanged renderFull renderMap renderAround renderLines renderSearch windowEnvelope fitWithin
索引: 全部缺失
跨度塌陷: renderDigest 报 69-69（真实 69-164）
```

用户可见后果：`map` 报 `755 lines · 16 symbols (variable:14 function:2)`，
`locate target=readWith` → `STRUCT_NOT_FOUND`。**本工具连自己的引擎都定位不了。**

**机制**：配置表里只有注释与字符串两类，正则字面量无处安放，于是 `/` 被当普通标点：

- 正则里的引号开了一个**字符串** token，把后面的代码整段吞掉
  （`/['"]/` 之后 `function after(){}` 消失）；
- 正则里的转义括号（`\(`）留下**不配对的 open**，而每个 `declarationSpan`
  与 `$param*` 跳过都依赖 `matchBrackets`——它一失衡，其后跨度全部错乱。

最小复现：`const R = /['"]/` + `function after(a,b){}` → `after` 消失。
`/[\w]+/` 与 `/\b(if|x)\b/g` 干净——**只有引号与转义会炸**。

**为什么这是补丁式缺陷**：本文件第 25-26 行断言"注释与字符串已经吃掉了，因此 symbol
规则永远不会被注释里的词触发"。那句话**是断言而不是实现**——正则字面量是第三类，
它在任何表里都不存在。所有消费 `pairs`／跨度的代码都继承了这份静默的错误。

**修法**（按本文件自己的设计约束：差异只进配置表，扫描器只有一份）：

1. 配置表加 `regexLiterals`；
2. 扫描器加一个分支：`/` 且 `previousTokenAllowsRegex(tokens)` 时按正则吃掉，
   跟踪字符类 `[...]`（`/[/]/` 里的 `/` 不是结束符），跳过转义；
3. 判据 `previousTokenAllowsRegex` **只看前一个 token**——只有前面不可能结束一个表达式时，
   `/` 才可能是正则开头。这是唯一不需要回溯猜测的通用规则。

**关键边界（第一版我改错了，已纠正）**：`regexLiterals` 最初挂在了 `C_LIKE_BASE` 上，
而那个 base 被 **10 个语言**共用。Go / Rust / Java / C# / Kotlin / Swift / C / Scala / Dart
**都没有正则字面量**，它们的 `return a / b` 是除法——拿到这一项后那个 `/` 会被当成正则开头
并吃掉后面的代码。那等于**用一个新缺陷换掉一个旧缺陷**。现已挂到 `C_LIKE`（只 JS/TS 继承）。

**效果**：

| | 修前 | 修后 |
|---|---|---|
| `read-core.mjs` 索引到的 function | 2 | 18（含嵌套） |
| `map` 符号数 | 16 | 125 |
| `locate target=readWith` | STRUCT_NOT_FOUND | line 395-480 |
| `locate target=renderDigest` | 69-69 | 69-164 |

**新增 `regex-lex-test.mjs`（51 项）**，其中最有价值的一条是**自指断言**：
四个引擎文件里每个顶层 `function` 都必须被索引到、跨度都不得塌陷、
`locate` 都必须能按名字命中。引擎若再度失明，**先看不见的就是它自己**——
这条断言不依赖我预想得到某个具体的破坏方式。

## 尚未处理的复核发现（按优先级，下一轮）

- **F2（high）**：`struct-core` 用 `endTok + 6` 的 token 窗口代替"语句在此结束"的规则。
  后果是箭头函数绑定丢函数体（`const done = (a,b,c) => {` 报成 `variable 58-58`，
  真实 58-71），`aura_edit target=done` 会只替换一行、留下函数体——**静默改坏文件**。
  多行 `type` 别名还会吞掉下一个声明。修法：以语句边界（`;`、未配对的 `}`、ASI 换行）终止跨度扫描。
- **F3/F4（medium）**：`aura-edit` 把 `locate` 已有的地址空值与 `expect` 判定各重写了一遍，
  且重写的那份更差——`line_cue:''` + `anchor` 会把兜底锚点丢掉；
  `PATCH_EXPECT_MISMATCH` 是死分支，而被丢弃的那条错误信息反而带 `actual`。
- **F5（medium）**：`byNear` 由引擎产出、在 `locator-api` 的 `done()` 处丢弃，
  而 `aura_edit` 回执、输出 schema、渲染都在用它——**"by near" 标记恒为 false**。
- **F7（medium）**：`PRUNE_BUDGET = 8192` 是宿主常量，却住在自称框架无关的引擎里；
  同处 `- 64` 与 `pass < 4` 是无说明的预留。
- **F11**：`windowEnvelope` 的截断披露修好了，但 `renderSearch`（110）、摘要签名（68）、
  候选行（80）仍在用裸数字截断且**不披露**——同一个决策四份实现，正是本次修的那一处所批评的形状。
