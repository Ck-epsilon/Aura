# dsh-tool-aura-edit

一个 DSH 工具插件：**用锚点补丁改文件，而不是重新输出字节**。

> 0.10.7 起同一插件还注册 **`aura_basetools_write`**：新建或整份覆写，保留 BOM/行尾、覆写默认要求先读过
> 这一版、落盘后回读校验。局部改动仍走 `aura_basetools_edit`；读图仍只有内置 `read_image`。

模型声明"改哪里 + 改成什么"，宿主负责匹配、消歧、落盘、回滚。相对内置 `edit` 的五点变化：

1. **五级降级匹配** —— `exact` → 空白折叠 → 行 strip → 字符 bigram 相似度 → **行级序列对齐**。
   缩进、行尾空格、制表符、改一两个词、重排一行都不再让补丁失败；最后一层连"锚点相对真实
   区域多/少了一整行"也能处理。
2. **`near` 位置提示** —— 歧义锚点用行号收敛。grep 早就知道行号，`edit` 却只认字节。
3. **一次调用多个 hunk，整体事务化** —— 任一 hunk 失败则磁盘完全不变。
4. **降级命中时带回调中的原文** —— 把"命中了但不是我以为的那段"这个**不可见失败**变成可见。
5. **`dry_run`** —— 只定位不落盘，先看命中在哪。

## 接口

```
patch(
  file_path: string,
  hunks: [{ target?: string, anchor?: string, replace: string, expect?: string, near?: integer }],
  dry_run?: boolean
)
```

每个 hunk 用**两种方式之一**定位（`target` 优先）：

- **`target`** —— 符号名。`toTodoList`、`function:apply`、`Outer/Inner`、`name#2`。
  **跳过全部文本匹配**，因此对"记错内容"完全免疫。知道符号名时优先用它。
- **`anchor`** —— 记得的原文。走五级降级匹配，容错空白/改词/增删行。
- `replace` —— 替换文本。空串 = 删除该区域。
- `expect` —— 可选闸门：你**确信**锚点位置应该是什么内容。对不上则整个补丁失败，绝不改不确定的区域。
- `near` —— 可选行号提示，解决歧义。
- `dry_run` —— 只定位不落盘，先看命中在哪。

**锚点失败时，错误里会附上该文件的结构目录**（符号名 + 种类 + 行范围）和一句恢复指令，
把"重猜一整段原文"变成"用符号名重试"。这是实测支撑的唯一组合方式，见下。

## 实测：定位策略对比（`locator-lab/FINDINGS.md`）

20 个真实区域 × 7 种文本扰动 = 140 个用例。**找对** = 返回区域包含真值；**定位载荷** = 模型为指明位置必须生成的 token。

| 策略 | 找对 | 命中错位 | 定位载荷 | 相对成本 |
|---|---|---|---|---|
| `edit`（逐字节） | 14.3% | 13.6% | 30.9 | 1.00x |
| `anchor`（文本锚点） | 58.6% | 16.4% | 30.9 | 1.00x |
| **`target`（符号名）** | **100%** | **0%** | **4.0** | **0.13x** |
| 域内锚点 / 组合拳 | 58.6% | 17.1% | 34.9 | 1.13x |

结论：**换掉问题的本体，比优化解法更值。** 文本匹配的四级降级把 14.3% 提到 58.6%；
换成符号身份直接到 100%，成本降到八分之一——因为它压根不读文本，文本怎么错都影响不到它。

### 符号目录的效果（实测）

`anchor` 的失败用例 100% 可被符号名救回。真实 dsh 里已验证：模型用 `target='classify'` 一次命中
（层级 `symbol`），且失败时的结构目录被完整交付。

## 设计要点（为什么不是 edit 的补丁版）

**匹配分五级，每级解决一类漂移，且各自有明确的适用边界。**

| 层级 | 处理 | 说明 |
|---|---|---|
| `exact` | 逐字节相同 | 最常见，也是最快的路径 |
| `norm-space` | 空白折叠 | 容错缩进、行尾空格、制表符 |
| `trim-line` | 行 strip | 容错行首行尾一切空白差异 |
| `similarity` | 字符 bigram | 容错改词、重排；**假设行数不变** |
| `aligned` | 行级序列对齐 | 处理**增删行**；返回对齐真实覆盖的跨度 |

前三级是"同一段文本的写法差异"，第四级是"同一段文本的词被改过"，第五级是"这一段的**行数**变了"。
把它们分成不同层级而不是揉成一个分数，是因为它们的失败原因互不相同，混在一起会让阈值无从标定。

**相似度用倒排索引，不是滑动窗口。** 朴素做法对每个起始位置算一次整块相似度，是
O(文件行数 × 锚点行数)，实测在大文件上能挂死。这里改成"所有窗口同时打分"：锚点每行用自己
**最稀有的 bigram** 去倒排索引取候选行，只在候选窗口上累加分数。大文件实测 8–21ms，
且不需要前置筛或兜底分支。

**候选起点由每一行的命中投影得出，而不只靠窗口打分。** 窗口打分有个盲区：被删掉的那一行若
正好是锚点首行，分数和候选池会一起塌掉。投影起点不依赖任何特定行匹配成功——只要某一行命中，
它就能给出"真实区域大概从哪开始"，交给对齐层裁定。

**代价函数与不相似度成比例（`2 × (1 - 相似度)`），不能是分段式。** 分段式（"相同→0，否则整额"）
会让一个字符的笔误与整行重写等价。实测：把"锚点少一行 + 一个标识符记错"算成两次整额代价后，
得分掉到 0.631，低于 0.7 的阈值而误判为找不到。比例式下同一个案例得分 0.93。

**事务性来自顺序，不是来自回滚。** 先把所有 hunk 全部定位、核对、查重叠，全部通过后才做一次
倒序拼接和一次 `editText`。因此不存在"改了一半"的状态，也不需要撤销逻辑。

**与 `dsh-tool-fs` 的 fs 契约完全一致**：`resolve` → `fs/edit-intent` 取守 → `fs.editText` →
`fs/observed`。所以 `fs-observation-policy` 和 `fs-sandbox` 对本工具同样生效。
本工具读取的是**完整文件**（比 read 工具的分页窗口更强），读后自行发出 `fs/observed`，
锚点比对本身则是比版本号更强的新鲜度检查：文件变了锚点就不会命中，宁可 `PATCH_NOT_FOUND`
也绝不按错位置改。

## 一次自我审计：曾经藏在这里的"补丁的补丁"

代码写完后又按"是否还有补丁式的做法"通查了一遍，找出四处用魔数或兜底分支盖住结构问题的地方，
已全部换成根因解：

| 曾经的做法 | 为什么是补丁 | 现在的做法 |
|---|---|---|
| `COMMON_BIGRAM_CUTOFF = 8`：出现超 8 次的 bigram 不索引 | 用次数上限去解决"空白 bigram 无区分度"，连带把出现 9 次的**普通代码 bigram** 也踢出去，那行就彻底无法定位 | 只跳过纯空白 bigram。真正的区分不是"常见/罕见"，而是**是否携带信息**；非空白 bigram 的价值随出现次数平滑下降，交给"取最小桶"自己处理 |
| 策略守取失败就静默降级为无守 | 守本身是多余的（见下），降级路径却让"守陈旧"变成一轮白白浪费的失败 | 直接不取守。可靠性来自锚点内容比对，不来自版本号 |
| `pickNear` 在多个候选**等距**时挑一个 | 这正是本工具要消灭的行为：`edit` 就是在多个位置里静默选中第一个 | 等距即返回 null → `PATCH_AMBIGUOUS`。`near` 区分不了就不该由宿主掷骰子 |
| 候选池按投影出现顺序截断到 5 个 | 顺序无意义，会把真正的最佳候选排除在外，凭空造出 `PATCH_NOT_FOUND` | 先按便宜的窗口分数排序，再截断 |

另外清掉了两处死代码：`probe` 预计算数组（建索引时算完却没人读）、`backtrack` 回溯函数
（跨度来自窗口宽度，配对位置从未被使用）。T2/T3 的按行归一化也从"每次定位重算两遍"
挪到了建索引时一次算好。

## 已知边界

- **降级命中会替换"工具matched 的那段"，而不是"模型以为的那段"。** 这是刻意的：
  回执会把实际命中的原文带回来，由模型核对。但如果不带 `expect` 闸门，而锚点又写错了，
  就可能没有改动地"成功"一次，或改到相邻的相似区域。**多 hunk 的批量改动请带 `expect`。**
- **`anchor` 与 `replace` 行数不同时，`expect` 闸门会拦下正确的补丁**：闸门按归一化后比较，
  而它的语义是"锚点位置应该是什么内容"。要删除或增补行时，请让 `replace` 自己包含完整的
  目标形状，或干脆不用 `expect`。这是刻意偏保守：不确定就不改。
- **锚点太短时"少一行"本质上是歧义的**：文件里若存在与被匹配部分完全相同的相邻行，
  任何匹配器都无法区分完整区域和它的子集。此时引擎返回 `PATCH_AMBIGUOUS` 而不是猜。
  用更长的锚点（带上下文的唯一行）可以消除这种歧义。
- **相似度阈值 0.82 / 对齐阈值 0.7 是仅有的两个经验参数**。它们只回答"这算不算同一段"，
  不参与性能决策。极端漂移（锚点里所有长标识符都被改写）实测 best ≈ 0.67，会被正确拒绝。


## 性能

实测（867–1824 行的真实源文件，含强制走相似度层的路径）：单次定位 **8–21ms**；
20 个 hunk 一次调用的事务处理 **4ms**。对齐层只在前四层都够不到阈值时启用，且只对
最佳的几个候选起点做。
