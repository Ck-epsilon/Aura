# 测试分层：接口 / 集成 / 系统

> 2026-10-27 起只保留三层。单元层已从闸门移除并归档到 `docs/archive/unit-tests`（不运行、不发货）。
> 新增测试必须属于三层之一；对单个内部函数、私有结构的断言不进发布闸。
> 判定权只在对外接缝：接口（CLI 命令 / MCP-json / DSH 工具 / 文件与退出码）、集成（跨模块接线）、
> 系统（装出去真跑、端到端、任务级成本）。

## 一张表

| 层 | 它问的问题 | 本仓套件 | 判据来源 |
|----|-----------|---------|---------|
| **接口** | 对外承诺的契约还在不在 | `public-surface` · `docs-surface` · `capabilities` · `schema-portability` · `surface-parity` · `arg-shape` · `range-args` · `read-schema` · `apply-contract` · `policy-arg` · `write-verify` · `stale-gate` · `byte-fidelity` · `encoding-fidelity` · `span-fidelity` · `encoding` · `encoding-refusal` · `preflight` · `retry` · `coverage` · `structure` · `probe` · `write` · `argument-surface` · `replace-all` · `single-line-target` · `observation-gate` · `already-applied-shell` · `repair-address-shell` · `doctor` · `entity-apply` | 真 CLI/MCP/DSH `execute()`、schema、退出码、回执正文 |
| **集成** | 几个部件接起来对不对 | `aura-read/load` · `aura-edit/load` · `aura-edit/align` · `read2` · `adapters` · `real-framework` · `installed-package` · `range-error-lifecycle` · `observation-store-identity` · `alias-identity` · `verify-edit` · `interrupt-posture` | 真 engine + mock/真 ctx；真 `dsh-tools`；真文件系统 |
| **系统** | 装出去、端到端还能不能用 | `standalone` · `range-bytes` · `observation-concurrency` · `concurrency-crash` · `tx-session` · `index-scaling` · `task-bench` · `perf-gate` · `post-publish` · `split-package` · `cli-mcp-e2e` · `embeddability` · `ci-contract` | 真进程 + 真 tgz/npm 安装 + 真文件 + 任务级 SLO |

一套件同时回答两层问题时，列在更靠近对外契约的那一层。

## 为什么单元层被移除

单元层直接断言 `struct-core` / `read-core` / `write-path` 的内部函数与私有结构。它们曾经是回归锚点，
但也会在重构而行为未变时变红，且不能回答“agent 用起来对不对”。现在把预算移到接口/系统层：
同样的字节保真、陈旧闸、编码、事务、并发、句柄和结构地址，由 `standalone` / `range-bytes` /
`write` / `tx-session` / `verify-edit` / `concurrency-crash` / `entity-apply` 从真实入口打。

## 单元层移除后的已知缺口（写出来才算数）

| 缺口 | 现在由谁兜 | 何时补 |
|------|-----------|--------|
| 解析器/语言规则/索引缓存的内部行为 | 接口层的 `structure` / `read-schema` 与系统层的字节/读靶场；具体语言的边角不再枚举 | 某个语言 bug 再次出现时，加一条**系统级**复现，不恢复单测 |
| 同址同文漂移（`coordinate-drift` 的独特用例） | `stale-gate` 覆盖区域闸；同址同文那一格没有直接判据 | 真实会话再出现时，加进 `entity-apply` 或新的系统套件 |
| 句柄的逐字节确定性 / 身份失配细节 | `structure`（CLI 结构句柄）+ `standalone` 的句柄段 | 句柄 bug 再现时补系统用例 |
| `multi-read` / `multi-edit` 的池内顺序与 N=1 短路 | `standalone` 的多目标段与 `argument-surface` | 采用率或并发问题再现时补系统用例 |
| 100k 符号索引的缩放 | `index-scaling`（系统层，保留） | —— |
| macOS / Linux 上的真实文件系统细节 | `ci-contract` 只证明 CI 配置；真机仍需 T5 | 有真机时跑 `release-check` 与 `split-package` |
| 图片 content 在真实客户端的渲染 | `entity-apply` 的 MCP image block + DSH `attachments` 分支 | 接一个真 MCP 客户端时补一条外部验收 |
| 仓库 grep 的 ReDoS / 超大仓 | `repo-search` 的长度/字节/命中上限；尚无压力靶场 | 上线前用真实大仓跑一次，超预算再加 worker/超时 |

## 跨层能抓到、单层抓不到的三件事

1. **mock 比真框架宽松**：工具描述符在真框架下不合法，mock 套件全绿。⇒ `real-framework`。
2. **“文件在”不是“能加载”**：`fs.existsSync` 全 true，宿主重启 `import()` 才炸。⇒ `installed-package` 与 `split-package` 的真 npm 安装。
3. **跨进程状态链**：单次回执对，两次调用之间的一致性（观测账本、令牌过期、并发多进程）只有真进程串起来才看得到。⇒ `cli-mcp-e2e` / `observation-concurrency` / `concurrency-crash`。

## 跑法

```bash
node build/release-check.mjs                    # 全量三层 + 靶场 + 包内 + 拆包 + 一致性
node build/release-check.mjs --json             # 机器读
node src/aura-standalone/test/entity-apply-test.mjs   # 单跑实体/apply/grep/image
node build/range-all.mjs                        # 三套靶场（字节/参数/错误闭环）
```

跳过 ≠ 通过：`real-framework` 在解析不到宿主 peer 时、`installed-package` 在本机没装时自报跳过，
这两类必须在 `SKIP_OK` 里逐条写明理由；**没登记的跳过按失败计**。每个套件在 `SUITES` 行里
带一条判据条数基线：删掉一条判据、或把一段塞进不会走到的分支，闸都会红。
