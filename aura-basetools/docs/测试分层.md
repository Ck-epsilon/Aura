# 测试分层：六类各问什么，本仓由谁回答

测试分类的价值不在命名，而在**它们问的问题不同**。同一个 bug 只会被其中一类抓到，
所以“哪几类没有”就是“哪几种 bug 看不见”。本页把六类与本仓的具体套件对上，
并写明每一类的**已知缺口**——缺口写出来才算数。

## 一张表

| 类 | 它问的问题 | 本仓的套件 | 判据来源 |
|----|-----------|-----------|---------|
| **单元** | 这个函数/判据对不对 | `read-test` · `read-test2` · `read-fidelity` · `struct-test` · `span-fidelity` · `write-verify` · `stale-gate` · `byte-fidelity` · `encoding-fidelity` · `lang-test` · `lang-coverage` · `regex-lex` · `layers` · `var-binding` · `fresh-judgement` · `differential` · `symbol-invariant` · `coordinate-drift` | 手写期望值 + 独立第二实现（`differential`） |
| **集成** | 几个部件接起来对不对 | `aura-read/load` · `aura-edit/load` · `aura-edit/align` · `policy-arg` · `arg-shape` · `range-args` · `intent-address`（意图地址解析 + 写路径） · `receipt-context`（改后坐标/新句柄） · `auto-budget`（宿主预算选模式） · `concurrency-crash`（锁/事务一致性），以及 `cli-mcp-e2e` 的 C/D 段 | mock ctx + 真 engine；跨进程用真 bin |
| **验收** | **对外承诺的契约还在不在** | `public-surface` · `embeddability` · `split-package`（两个 npm 包离线装好之后真能用） · `task-bench`（8 个真实读+改任务的成本 SLO） · `perf-gate`（1k/10k/100k 行性能包线） · `post-publish`（发布物 = 被测物） · 本仓的 `install-test` | 导出面 / 插件四件套 / bin / package.json / README 里的路径；拆包走**真 npm 安装**；任务基准走真 provider；发布物走真 tgz |
| **冒烟** | 最关键的那条路能不能起来 | `real-framework`（真 `dsh-tools` 注册 + 真校验器）· `installed-package`（装出来的那份能不能 import） · `doctor`（CLI 自检：入口/握手/缓存与锁） | 真框架的真函数；真安装目录；真子进程 |
| **回归** | 修过的 bug 没回来 | 不单列——**每个 bug 都附一条断言**，散在上面各套件里 | 每个 bug 当时的实测输出 |
| **端到端** | 用户从入口到结果整条路 | `cli-mcp-e2e`（CLI/MCP 真进程，多次调用串起来）· `install-test`（装→升级→回滚→卸载）· `standalone-test` / `range-bytes-test`（真 bin） | 真进程 + 真文件 + 退出码 |

## 为什么“回归”不单列一个套件

单列一个 `regression-test.mjs` 会诱使人把**所有**历史 bug 的断言搬进去，
于是它与各套件的上下文脱钩：一条断言离开了它测的那个函数、那个夹具、那段解释，
就只剩一句“这里曾经错过”。本仓的做法是**把断言留在它该在的地方**，
并在断言旁边写清“当年实测到的形状”与“修复依据”。好处是失败时诊断信息就在手边：

```
✗ aura_basetools_read 读文件（full）→ 输出通过真校验
  "value.text" is not a declared property (additionalProperties: false)
```

——这一条断言的注释里就写着当年那次事故的完整经过。

## 每一类的已知缺口（写出来才算数）

| 类 | 缺口 | 为什么现在补不上 |
|----|------|-----------------|
| 单元 | 无结构性缺口（T2 Erlang 函数子句与 T28 Rust `pub const` 已修，均有正向断言） | —— |
| 集成 | 与**真 Cordis 加载器**的集成（本套件用真 `dsh-tools` 的函数，但不启一个真 Cordis 实例） | 起一个真宿主需要一份完整的 bundle + profile，属于端到端范畴 |
| 验收 | `docs/` 里除 `embed-example` 之外的文档**没有**路径检查 | 实测 `docs/待办.md` 18 条裸路径里 3 条对不上：2 条是**历史账**（记的是当时的文件名，过期才是对的）、1 条是散文被正则切出来的假路径。判据套在那类文档上会变成噪声 |
| 冒烟 | 干净机器上的**首次**安装（本机 peer 探测命中，但是“这台机器”的布局） | 需要一台没装过 dsh 的机器 |
| 回归 | 无结构性缺口 | —— |
| 端到端 | macOS / Linux 真机（T5）；`--from https-url`（代码路径在，未联网实测） | 需要别的机器 / 外网 |

## 跨层能抓到、单层抓不到的三件事（都实测过）

1. **mock 比真框架宽松** —— mock 不校验 schema，于是“工具描述符在真框架下不合法”会全绿通过。
   本仓被这一形态咬过**四次**（`text` 未声明 / `dry_run` 未声明 / `replace_all` 被拒 / `expect` 字段跟丢），
   每次都是“每条成功路径被框架拒”而套件全绿。⇒ `real-framework` 这一层。
2. **“文件在”不是“能加载”** —— `fs.existsSync` 全 true 而 dsh 重启后 `import()` 抛
   `ERR_MODULE_NOT_FOUND`（缺宿主 peer）。⇒ `installed-package` 与 `--doctor` 的 `loadable`。
3. **跨进程的状态链** —— 单次调用的回执对，但两次调用之间的一致性（观测账本跨进程活着、
   令牌过期被拒、并发多进程不丢更新）只有把真进程串起来才看得到。⇒ `cli-mcp-e2e`。

## 跑法

```bash
node build/release-check.mjs              # 全量（含上面全部套件 + 靶场 + 包内 + 安装器 + 一致性）
node build/release-check.mjs --json       # 机器读
node src/locator-lab/public-surface-test.mjs   # 单跑某一类
```

两个套件会**自报跳过**（并印得显眼）：`real-framework` 在解析不到宿主 peer 时、
`installed-package` 在本机没装时。跳过的报告里写着“这不等于通过”——
一个悄悄跳过的套件等于不存在（本仓曾因此漏掉过恒红的断言）。
