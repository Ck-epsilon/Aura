# aura-tools 0.6.17 —— 句柄寻址也补到三个面：能力面按「可能性」给全，不按采样率

0.6.16 把 `targets` 补到了 CLI 与 MCP。这一版补的是**另一个能力**，起因是一条口径裁定。

## 起因：验收口径从「采样率」改为「能力面」

用户原话（2026-10-16）：

> 不用管真正的多目标采样率是多少。客户怎么使用 aurabridge 的可能性都有，不应该被现状禁锢。

于是判据⑤（「装上多目标后 agent 真的改用它」）**不再作为验收门**：采样率照旧量、照旧披露，但它只作读数。
验收改看**能力面**：同一个能力在 **DSH 工具面 / CLI / MCP** 三个面上都必须**可用**，并且在各自的
**参数表里声明过** —— 模型看不见的能力，等于没有。

这条口径当场逼出一个真缺口。

## 缺口：句柄给得出、用不上

0.6.10 引入的句柄寻址（读回执发行尾柄 `<h9f3ac1b2e4d5:120-160>`，编辑用「句柄 + 段内相对定位」）
在三个面上的状态是**参差的**：

| 面 | 运行时 | 声明面 | 结果 |
|---|---|---|---|
| DSH 工具面 | 能用 | `handle`/`line`/`position` 早在参数表与描述里 | ok |
| CLI | 能用（`--hunks` JSON 里带 handle 就落盘） | 平铺旗标没接 ⇒ `--handle … --line 2 --replace X` 报「需要 hunks 或一组地址旗标」 | 脚本用户只能手写转义 JSON |
| MCP | 能用（`tools/call` 带 handle hunk 真落盘） | `HUNK_SCHEMA` 只有 9 键，**没有** `handle`/`line`/`position` | 走 MCP 的宿主（Codex / Cursor / Zed）**看不见这条路** |

最刺眼的一处：**CLI 与 MCP 读出来的回执正文里明明带着句柄**（`"handle":"h7e9c32b3d6cb:1-3"`），
而写回去的路在这两个面上没有声明 —— 给得出、用不上。

## 改了什么（引擎一行未改）

- `bin/aura-mcp.mjs`：`HUNK_SCHEMA` 增加 `handle` / `line` / `position`（9 → 12 键，`required` 仍只有 `replace`），
  三段描述与 DSH 壳**同语义**：句柄优先于 `old`/坐标、被让开的一方在回执里点名、`line` 越界走正常 `not_found`、
  `position` 只插边界不改区间本身。
- `bin/aura.mjs`：平铺旗标接上 `--handle`、`--line`、`--position`（直接递进引擎那套 `flatHunk`/`HANDLE_SHAPE_KEYS`）。
  **从属键语义保持**：`--line` 单独给（没有 `--handle`）**不构成一次编辑**，仍 exit 1 且磁盘不动 ——
  这正是堵住「`lines` 误写成 `line` 变成一次成功的错误编辑」的那条纪律。

## 判据

`src/aura-standalone/test/standalone-test.mjs` 新增 **MT-L**（12 → 独立面套件 **170 条**，src 形态）：

- ① MCP 的声明面必须有那三个键（改前必红）；② MCP 的句柄编辑真落盘且 `tier` 含 handle；
  ③ CLI 平铺旗标真落盘（改前必红）；④ 从属键语义（`--line` 单独给仍拒、`--position` 不动区间）；
  ⑤ **三面一致**：同一个句柄、同一次改动，CLI / MCP / 引擎直调三条路的 `tier` 与落盘**逐字节相同**。

成对证据：只加判据、两面未改 ⇒ **162 通过 / 8 失败**（逐条点名）；改后 ⇒ **170 通过 / 0 失败**。
变异反证：拿掉 MCP schema 里的 `handle` ⇒ 169/1 且只红 ①，按字节还原 ⇒ 回绿（sha256 三元组 A→B→A）。

一条实测记下来的不变式：MT-J 那 12 条单目标**逐字节黄金集不锁版本号** ——
「0.6.16 → 0.6.17 → 还原」实跑过，12/12 全绿。抬版不会假红；反过来，哪天它把版本吃进去，就是量具坏了。

## 仍然如实记着的

- 采样率那一格（重启后窗：多目标调用 2 次 / 占文件工具调用 0.4%）照旧披露，**但不再作门**。
- 能力面清单是**按已知能力逐面过的**（多目标 / 句柄 / 四态回执 / 修复地址 / 非 UTF-8 + 字节保真 + 陈旧闸门）；
  清单本身可能还有漏项 —— 漏项和「模型看不见」是同一个失效面，所以**复核方式**写进了交接单，便于别人复跑。
- 「修复地址」那一行标 done（待逐面复核）：复核没做完之前它算 partial。
