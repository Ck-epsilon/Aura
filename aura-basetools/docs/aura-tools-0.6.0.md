# aura-tools 0.6.0 —— 目录即地图、地址一致性闸门、拼错的参数不再被吞

以 0.5.3 版本说明写下时（9/22 00:49）为界，出厂面 17 个可比文件里 **16 个**动过——
只 `locator-lab/anchor-core.mjs` 一个字节未动。本版三件是**新增能力**，三件是**把以前会静默走过去的地方拦下来**。

## 一、`file_path` 指向目录 ⇒ 直接给一张仓库地图（T26）

新引擎 `repo-map.mjs`（纯函数 + 可注入目录源），两个入口面共用：DSH 壳与独立 CLI/MCP。

**没有新参数**：`mode=repo` / `scope=repo` 都没加。"这个路径是目录"工具自己看得出来，
让模型多填一个参数只是多一次决策——实测模型主动选 `mode` 的比率只有 **4%**，它宁愿让工具选。

三个仓的实测（同一台机器）：

| 仓 | 模块 | 目录 | 耗时 | 输出 / 预算 |
|---|---|---|---|---|
| `aura-tools/src` | 64 | 6 | 29 ms | 1597 / 7600 |
| agent-browser-bridge | 1266 | 72 | 272 ms | 4947 / 7600 |
| AuraPolaris | 881 | 263 | 540 ms | 5298 / 7600 |

三个参数都是先量再定的，不是拍的：

1. **遍历 vs 读头条**：给每个源文件读 8 KiB 头，2884 个文件要 **14.1 秒**；只遍历目录 **107 ms**。
   所以内容读取只发生在被选中的少数文件上（本版定 `maxSampled: 120`）。
   十几秒的探索工具没人会用第二次——这不是优化，是可用性分界。
2. **冷读 vs 热读**：同样 120 个文件，冷盘 **638 ms**、缓存热 **8 ms**。探索仓库本来就是冷启动场景。
3. **输出预算 7600** = 框架剪枝阀 8192 − 信封余量，与 `directoryHint` 同一条依据。

## 二、写路径补上"地址一致性"闸门（T21）

原判断是"拿旧观测的行号去改，区域恰好没动时会误判"。**用真引擎跑的五例探针把它证伪了**：
行号位移后同一行号上的文本通常已经不同，老判据（同址文本比对）照常拦住——

```
观测 one/two/three/four/five，第三方删掉前两行 ⇒ 当前 three/four/five
  地址 lines=[3,3]：观测同址 "three"，当前同址 "five"  ⇒ 老判据就拒了
```

五例里四例如此，**没有一例是"丢失更新被放过"**。真正的盲区只有一个：
同址文本**恰好相符**时位移读不出来。

```
观测 three/aaa/three/bbb（"three" 出现两次）
第三方在顶部插一行 ⇒ 当前 zzz/three/aaa/three/bbb
  地址 lines=[3,3]：观测同址 "three"，当前同址 "three"  ⇒ 老判据放行，但模型指的是另一行
```

补这一点用了**四版判据，全部被真实场景证伪**（四例都钉进了 `coordinate-drift-test`）：
第一版要求"这段文本在文件里只出现一次"，被重复行是常态打回；后续几版各自被别的真场景打回。
最终判据住在 `write-path.mjs` 的 `staleConflicts` / `staleRegionRefusal` / `regionGate`，
**壳、CLI/MCP、测试共用同一份**——判据只有一份，三面不可能跑出不同结论。

## 三、拼错的参数不再被静默吞掉（T31 审计）

拿**真框架**当裁判才发现的：真校验器只在 `parameters.additionalProperties === false` 时才拒未声明属性，
而框架**不会剥掉**它们——未声明参数原样到达 `execute`。于是把 `mode` 拼成 `mod`：

```
① file_path 单独           → mode=full  len=7722
② mode:'map'（已声明）     → mode=map   len=7614   ← 字段确实到达 execute
③ mod: 'map'（未声明）     → mode=full  len=7722   ← 被丢掉，零反馈
```

工具只读 `args.mode`，于是按默认行为跑并回一个**成功**回执；模型看到成功，就以为参数生效了。

两处一起修：schema 补 `additionalProperties: false`（声明面自洽）+ 运行期守卫 `assertKnownArgs()`（两个壳共用），
报错直接列合法键名。**规模**：16817 次真实调用里会被这条拒的只有
`limit×13`、`offset×10`、`line_cue×2`、`start_mode×1`、`sandbox_permissions×1`，**全在 `aura_read` 侧**。
其中 `limit`/`offset` 本意是分页，而本工具的分页参数叫 `start_line`/`end_line`——
静默忽略的结果是"模型以为自己翻页了"。**报错是修好，不是收紧。**

## 四、25% 的按名编辑，回执里原来印的是两个 `undefined`（T18）

新增 `symbol-invariant-test`——本项目第一条**属性测试**：随机挑真实语料、随机施加**不破坏语法**的扰动、
随机挑符号，断言性质本身。期望值不是人写的，是从扰动前后两份索引各自独立算出来的。

三条性质各对应一个真实失效形态：**存续性**（名字还在却寻不到）、**跨度可信**（命中区间取出的文本真的含那个名字）、
**幂等**（同一份内容两次解析逐字相同）。扰动必须语法合法（只改缩进量 / 末尾追加注释行 / 把空行换成注释行）——
随机插乱码会让"寻不到"变成**正确行为**，断言就成了假阳性；随机源是确定性 LCG，属性测试必须可重放。

顺着它当场量到一个以前没量过的数（本仓 7 文件 / 662 个可寻址符号）：

```
直接命中 497（75.1%）   需要消歧 165（24.9%，全部 STRUCT_AMBIGUOUS）
失败里可恢复的：165 / 165（#N 或 near= 都能寻到）
```

而**修复前的回执印的是 `candidates: line undefined, line undefined`**：候选算出来了却没印出来，
两个 `undefined` 看起来像"真的没有候选"。那是 **25% 的按名编辑**里模型能拿到的全部信息。
现在格式化器在**一处**归一两种候选形状，并直接给出**可直接用的地址**（`target=<名>#<序号>`）与消歧写法（`near=<行号>`）。

## 五、写失败的构成拆到分类级（T29）+ 服务化安装（T30）

不满足于"写失败 16.3%"这个总数，把它拆开才知道该修哪个：**`PATCH_EXPECT_MISMATCH` 548 次 = 写失败的 55.7%**，
其中 **77.5%** 在下一次编辑里自纠、只有 **0.4%** 原样重发；`LOCATOR_AMBIGUOUS` 116 次、**83.2%** 可恢复。
结论是"该修的不是匹配算法，而是**失败回执的可操作性**"——这与第四节那 25% 是同一个病灶。

发布目录里同时躺着两个 `.tgz` 时，默认来源该挑哪个，旧实现是 `.sort().pop()`（字典序）——
而字典序里 `0.9.0` 排在 `0.10.0` **后面**（'9' > '1'）。这个错误只在**跨大版本**那一刻现形，
本版按数字段比修掉，并把它钉成一条会红的夹具（`install-test` J1/J2：故意让"字典序最大"的那个是坏包，
判据对照证明坏包真的装不上）。

安装面从"一键安装"长成"可服务化"
失败自动回滚）/ `--rollback` / `--check --manifest`。同版本号两份不同字节由
`UPGRADE_SAME_VERSION_DIFFERENT_BYTES` 挡住——那正是 0.5.3 时期真实踩过的坑。

## 六、测试从"跑套件"变成六类分层（T32）

单元 / 集成 / 验收 / 冒烟 / 回归 / 端到端各问不同的问题，**"哪几类没有"就是"哪几种 bug 看不见"**。
本版补上原来是空的验收层、冒烟层、端到端层（矩阵与各类的已知缺口见 `docs/测试分层.md`）。

加测试时抓到的最值得记的一条：新写的验收套件第一版**是松的**，两次故障注入都没能让任何套件变红。
追下去发现一条"引用必须存在"的断言实测只覆盖 16 条引用里的 **1 条**——README 把脚本清单写在代码围栏里，
而旧正则要求路径被反引号包住。**这条断言 94% 是盲的，却一直是绿的。**
现在扫全文，覆盖面 16/16，四条注入（裸路径新增、真实路径改坏一个字符、骨架引用改名、删掉一个对外导出）逐条复验变红。
