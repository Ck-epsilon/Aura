# aura-tools 0.6.1 —— 体检能看见 profile 那一侧的第二份安装

0.6.0 已发并实装。这一版只有一个改动，但它补的是**一类**以前谁都看不见的病。

## 起因：一个活了 8 天的 0.2.1

本机 `~/.dsh/profiles/auratest` 是 2026-09-21 23:07 建的实验 profile：它把 aura-tools 声明成
**bundle 依赖**，指向 `dist/aura-tools/aura-tools-0.2.1.tgz`——而那个 `dist` 目录后来整个没了。
`dsh --profile auratest` **真的会**加载那份 0.2.1 的 `aura_read` / `aura_edit`。

它躺了 8 天，而这 8 天里：

- `--doctor` 说**全部正常**；
- 三面版本（CLI / MCP / DSH）全绿；
- 完整性、注册项、CLI/MCP 自检全绿；
- 34 套测试、三套靶场、安装器、升级、审计探针全绿。

**全都绿，因为没有一条判据会往 profile 那一侧看一眼。** 那些检查只看得见本安装目录；
而 `auratest` 是**另一份字节**，在另一条路径上，谁也不管它。

> 这是本项目最贵的一类失效：不是"某条断言错了"，而是"**没有任何断言在那个方向上**"。

## 改法：把那一侧钉进体检

`--doctor` 新增一行，扫 `~/.dsh/profiles/*` 与 `profiles/node_modules`，问一个问题：
**除了本安装目录，还有没有第二份 aura-tools？** 三种形态分开报，因为修法不同：

| 形态 | 输出 | 修法 |
|---|---|---|
| 声明了却没装 | `…声明了 aura-tools 但没装 —— 那个 profile 现在起不来` | 补装或删掉它 |
| 装了，但声明的包体已不存在 | `…自带 aura-tools 0.2.1，但它声明的包体 <路径> 已经不存在 —— 补不回来` | 删掉 profile，或改指本安装目录 |
| 装了，版本与本安装不同 | `…自带 aura-tools 0.2.1（本安装是 0.6.1）—— 这是**另一份字节**，安装器升级不到它` | 同上 |

三种都计进"需要处理"（fail-closed）。干净时**也要说话**——
`其它安装  : 看了 3 处（共享 node_modules、headless、web），没有第二份 aura-tools`：

> 体检里最坏的一种绿是"我压根没看"。所以这一行必须报出**到底看了哪几处**，
> 让"查过了、没有"与"根本没查"在输出里能分开。

稳定路线（profile 的 `cordis.patch.yml` 指向本安装目录）**不会**在这里报任何东西——
那条路线不在 profile 里放局部的 `node_modules/aura-tools`，三面本来就是同一份字节。
判据因此不会惩罚正确做法。

## 同一次清理

`auratest` 这个 profile 已按用户要求整体删除（它依赖的包体不存在、且是一份会真加载的旧字节）。
删之前把配置文本留在 `~/.dsh/.removed-profiles/auratest-<时间戳>/`（含 `REMOVED.txt` 说明来历），
那份没价值的 0.2.1 载荷没有留。删后 `dsh --profile auratest` 明确报"profile 不存在"，
`web` / `headless` 组合结果不变（仍指向 `~/.aura/pkg/node_modules/aura-tools/…`）。

## 验收

`install-test` **48 → 52**（新增 K1–K4，四种形态各一条）；全量闸门 34 套 + 三靶场 + 包内 70/70 +
安装器 52/52 + 升级 94/94 + 审计探针 31/31 + `src↔dist` 一致 + 三面版本均 0.6.1。

**注入验证**（这条判据本身也要被测）：把体检里那段调用换成空结果 ⇒ **K1–K4 全红**；
恢复 ⇒ 52/52。也就是说这不是"加了条输出"，而是一条真的会拦人的判据。
