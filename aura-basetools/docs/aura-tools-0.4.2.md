# aura-tools 0.4.2 —— 三套靶场打出来的三条修复 + 一条过程教训

**为什么有这一版**：0.4.1 之后我们建了三套靶场（格式矩阵 3351 条断言 / 字节形态 217 条 / 参数形态 76 条），
一晚上打出来的结果：**源码级缺陷 3 条**（都在 CLI/MCP 面）、**过程缺陷 1 条**（产物落后于源码）。
本版把 3 条修掉，并把第 4 条变成机制。

## 三条修复（都是"说好了有、其实没有"这一类）

| # | 问题 | 现象 | 修法 | 证据 |
| --- | --- | --- | --- | --- |
| **F3** | `changed` 在"没差异"时不返回 `text` | 其它六个模式恒有 `text`，只有它给 `note`。调用方（尤其模型）会把**字段缺失**读成"文件是空的"——静默换语义的另一种形态 | 四条"没内容可给"的分支都补上 `text`（内容就是那句说明） | 修复前字段 `[ok,mode,totalLines,contentBudget,version,note,next]`（无 text）；修复后 `changed` 无差异也带 `text` |
| **F5** | **结构化错误证据到不了 CLI/MCP 回执** | `PatchError` 把证据挂在错误对象自身（`candidates`/`minimal_next`/`others`/`write_verify`/`actual`…），而 `lib/ops.mjs` 只转发一个**全仓没人设过**的 `detail` → CLI 与 MCP 上这些字段全丢，只剩人类可读的 message | 新增 `errorEvidence()`：按**排除法**转发错误对象上的自有字段（排除 `code/name/message/stack`），以后加字段自动带上 | 实测 `LOCATOR_CUE_AMBIGUOUS` 的确带 `candidates`；修复前回执里没有它 |
| **F6** | **`--max-chars` 是空开关** | CLI（`--max-chars`）与 MCP（`max_chars`）都暴露了这个参数，`readWith` 却从没读过它——四档取值（无/100/2000/400000）回执完全一致，预算恒为 7550 | `readWith` 接上它：作为**上限收窄**预算；更大的请求由流水线硬上限兜住（"输出绝不越过剪枝阈值"是硬保证，不能被参数推翻） | 修复前 4/4 档 `contentBudget` 相同；修复后按 N 收窄 |

## 一条过程教训：同一个版本号下可能有两份不同的字节

参数靶场报的三条"缺口"（dist 上：半坏区间静默缩成单行、半坏 hunk 静默改坏文件、CLI 的 `--lines` 静默退回 auto），
**根因不是源码，而是我改了源却没有重建 `dist/`** —— 于是 `0.4.1` 这个版本号下同时存在两份不同内容的包：
源码是修好的，产物是旧的。任何直接吃 `dist/`（CLI、MCP、tgz、zip）的调用方都会命中旧行为。

这次靠靶场抓住了（它们写成 `gap()` 独立成节打印，重建后自动**提升为 `check()`** —— 重建后参数靶场从 73 条涨到 76 条全绿，
就是这三条从"缺口"变成"必须通过"）。但这不是可以靠运气的事，本版做了两件事：

1. **重建纪律**：改源 → 立刻 `make-bundle --pack` → 复跑（本版的顺序就是按这个走的）。
2. **写进升级设计**：版本号**不足以**标识产物，`docs/服务化升级设计.md` 的 P0 清单里加了"内容哈希/构建戳"一项 ——
   `--doctor` 要能回答的不只是"是不是 0.4.2"，而是"**这份字节**是不是我以为的那份"。

顺带修掉一个自己造的毛病：靶场文件被 `test/` 一起打进包里（包体 18 → 19 个文件），
而它们按**项目布局**找路径、在包里跑不起来。**不发跑不动的东西**：`make-bundle` 现在排除 `range-*.mjs`，
包里只留在包内真能跑的验收（`standalone-test.mjs`）。

## 已知边界（靶场自己声明、我认可）

- 格式靶场：不碰落盘链路（归 byte-fidelity/encoding/stale-gate 与字节靶场）；夹具都是最小夹具，不覆盖内容预算截断；
  Unicode 不做 NFC/NFD 归一断言；`LANGS` 里未点名的 `mts cts pyi cc cxx hh ksh psm1 psd1 pxd pxi` 无夹具。
- 字节靶场：阈值判据只用纯 ASCII 验证（多字节口径未测）；无真并发压测；编码域只覆盖 UTF-8。
- 参数靶场：未启动 dsh，因此"宿主注册期是否会报 `UNSUPPORTED_SCHEMA`"只有静态判据；源码 CLI 在 src 布局下不可运行（只有静态断言）。
- `"lines": 412, 500` 这类**非法 JSON** 依然只能由宿主拒——工具拿不到参数（0.4.1 已说明）。
